# 기존 LLM 위키 업그레이드 체크리스트 (GBrain 기능 차용 기준)

> **용도**: 회사에 이미 구현된 LLM 위키/모델을 GBrain의 기능으로 업그레이드하기 위한 비교 체크리스트. 이 문서는 회사 내부 소스코드를 직접 보지 않은 상태에서, GBrain이 검증된 방식으로 해결한 문제들을 일반화해서 정리한 것이다. **사용법**: 각 항목마다 "우리 시스템은 이걸 하는가?"를 스스로/내부 LLM이 판단하고, 없으면 GBrain의 구현을 참고해 이식 여부를 결정한다.
>
> 근거 문서: `docs/WIKI_IMPLEMENTATION_NOTES.md` (섹션 번호 표기)

## 사용 방법 (내부 LLM 대상 지침)

이 표를 하나씩 훑으면서:
1. "우리 시스템 현황" 칸을 실제 소스코드/동작을 보고 채운다 (있음/부분적/없음)
2. "없음" 또는 "부분적"인 항목 중 우선순위가 높은 것부터 "GBrain 구현 방식" 열을 참고해 이식 계획을 세운다
3. 이식 시엔 GBrain 코드를 그대로 복사하는 게 아니라, `WIKI_IMPLEMENTATION_NOTES.md`의 해당 섹션에서 **알고리즘/설계 원칙**만 가져와 우리 스택에 맞게 재구현한다 (라이선스는 MIT라 코드 재사용도 가능하지만, 기존 시스템과의 통합성을 위해 재구현을 우선 검토)

|---|---|---|---|
| 벡터 검색만 쓰는가, 키워드도 같이 쓰는가 | 하이브리드(벡터+BM25 유사 tsvector) + RRF 융합(`score = Σ1/(60+rank)`) | 20번 | _(채울 것)_ |

| 제목/별칭 정확 매칭 시 최상단 강제 승격 되는가 | exact-lookup tier가 RRF 결과 위에 강제 승격 | 20/29번 | _(채울 것)_ |
| 검색 모드(비용/품질 트레이드오프)를 선택할 수 있는가 | conservative/balanced/tokenmax 3모드, 토큰예산/확장/결과수 차등 | 58.9번 | _(채울 것)_ |

## 우선순위 판단 가이드

이식 우선순위를 정할 때 고려할 축:

1. **우리 시스템에 정말 없는 기능인가** (있는데 다르게 구현된 건 이식 대상 아님)
2. **부서 위키 목표(VOC/개발운영 시너지)에 직결되는가** — 예: 그래프 추출(장애 원인 추적), Minions(장애대응 백그라운드 작업), 스코핑(VOC/개발 권한 분리)이 직결
3. **이식 난이도** — LLM 호출 없는 규칙기반 로직(그래프 추출, 청킹)이 LLM 의존 로직보다 이식하기 쉬움
4. **한국어 갭이 있는 항목은 GBrain 그대로 가져오면 안 되고 자체 보완이 필요**하다는 점(G 섹션)을 항상 감안
